# Gemini 3.5 Flash-Lite — viabilidade e configuração (2026-11-17)

Avaliação empírica da troca do provedor de IA do SynapseShop para
`gemini-3.5-flash-lite` nos três pilares (`assist`, `sql` e `docs`), com a chave
de demonstração já configurada no `.env` local. Nenhuma chave, token ou corpo de
requisição foi versionado ou impresso.

## Metodologia

- `client.models.list()` para confirmar a disponibilidade do modelo — não
  consome cota de geração.
- `client.models.generate_content()` com `google-genai 1.75.0` e
  `HttpOptions(timeout=30_000–45_000 ms)` para medir latência, erro e uso de
  tokens em prompts curtos.
- 8 tentativas de `generateContent`: **5 respostas válidas**, **2× HTTP 400**
  e **1× HTTP 504**. A tentativa com `thinking_level` falhou na validação local
  do SDK (parâmetro desconhecido) e **não** chegou à API.

## Disponibilidade

`client.models.list()` devolveu **64 modelos**, incluindo
`gemini-3.5-flash-lite` e `gemini-3.5-flash`. O modelo existe para a chave
atual; a troca não depende de nova credencial.

## Conclusões

1. **`thinking_budget=0` é o bloqueio.** O Flash-Lite rejeita zero com HTTP
   400. Como erro 400 é terminal na taxonomia do `LlmService`, o modo `auto`
   **não** cai para o mock — trocar apenas o nome do modelo causaria 502 em
   todo `/assist`.
2. **O modelo padrão anterior já estava instável.** O controle com
   `gemini-3.5-flash` estourou 30 s com 504; o Flash-Lite respondeu em
   3,5–4,1 s quando aquecido.
3. **`temperature` não é o problema.** É aceito, porém depreciado e ignorado
   nesta geração, assim como `top_p`/`top_k`. Turnos `model` pré-preenchidos
   viram 400 — os três fluxos atuais terminam em `user`, então não há risco
   hoje.
4. **`thinking_level` exige upgrade de SDK.** O `google-genai 1.75.0` não
   conhece o parâmetro; upgrade ficou fora deste incremento. A solução adotada
   foi `LLM_THINKING_BUDGET`: vazio omite `thinking_config` (padrão do Lite),
   `0` continua disponível para modelos legados.
5. **Custo.** A página oficial de preços publica US$ 0,30/1M de entrada e
   US$ 2,50/1M de saída para o Flash-Lite — já eram os defaults do
   `.env.example`, agora alinhados também no `docker-compose.yml`.

## Cota (observação datada)

Os limites da free tier são **por projeto e por modelo**:

| Modelo | Limite | Origem |
| --- | --- | --- |
| `gemini-3.5-flash` | 20 requisições/dia | medido em 2026-11-16 (HTTP 429 `RESOURCE_EXHAUSTED`, ver `2026-11-16_gemini-indisponivel.md`) |
| `gemini-3.5-flash-lite` | 15 RPM / 500 RPD | informado para a chave em 2026-11-17 |

Não existe endpoint público que devolva a cota da chave; os números devem ser
confirmados em `aistudio.google.com/rate-limit`. Com 500 RPD, o golden set de
58 itens cabe em uma janela — use `python scripts/avaliar_ia.py --delay 4`
(teto de 15 RPM; com a latência real, o run fica em ~6–8 RPM).

## Validação na stack

Após a alteração de código, `docker compose up -d --build db api dashboard`
subiu a API com o novo default e `python scripts/validar_compose.py` fechou
**5/5**. O smoke ponta a ponta `python scripts/validar_mvp.py` passou **13/13**,
com os três pilares em Gemini real:

- `/assist/` — 200, resposta de 382 caracteres;
- `/ask_sql/` — 200, 4 linhas, `modelo=gemini-3.5-flash-lite`;
- `/ask_docs/` — 200, 1 fonte citada.

`/api/v1/llm/metrics/` reportou `provedor_configurado=auto`,
`provedor_efetivo=gemini`, `modelos={assist,sql,docs}=gemini-3.5-flash-lite`,
`fallbacks=0` e custos `0.30/2.50` USD por 1M tokens. Ou seja: o HTTP 400 do
`thinking_budget=0` não ocorre mais e não houve fallback para o mock.
